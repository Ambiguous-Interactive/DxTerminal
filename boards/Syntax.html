07 · SYNTAX, ARGUMENTS, COMPLETION

The line you type is colored by the parser that runs it

Every token is classified by CommandTokenizer and the command's own CommandArgument.TryParse. Color, completion and the error you see before Enter can never disagree with what runs after it.

Theme: use the Tweaks panel (Dx Dark, Dx Paper, Phosphor)

B1 · TYPING A COMMAND: GHOST TEXT + LIST

↑↓ selectTab accept→ accept wordEsc dismiss4 matches
› spawn

Ghost text shows the selected item inline, as fish and PSReadLine do. The list is vertical so descriptions fit, and names sit in a fixed column so descriptions align. A type badge appears only when a list mixes kinds, such as commands and variables. Matched characters are underlined as well as tinted, so the match reads without color.

B2 · ARGUMENT: SIGNATURE HELP + TYPED CHOICES
goblinHP 30
ghoulHP 55
golemHP 400
prefab · 1 of 3 arguments
Enemy to spawn. Lists prefabs under Resources/Enemies.
spawn prefab: goblin|ghoul|golem [count: int 1–50 = 1] [at: Vector3 = player]
› spawn goblin

The signature line uses the same type colors as the input, so int 1–50 above and 12 below read as the same kind of thing. The active argument gets the selection fill. Optional arguments are bracketed and show their default.

E · WHY FOUR HUES, NOT SIX

On a dark input, text must be light, and light colors lose their hue difference for color-blind readers. Measured with the palette validator, all pairs, against #0A0E13 (dark input) and #F4F1EA (paper surface):

5 hues, 4 tries■ fail · protan ΔE 0.9–5.5
Dx Dark, 4 hues✓ pass · CVD ΔE 13.1 · normal 16.1
Dx Paper, 4 hues■ fail · deutan ΔE 4.6
Dx Paper, 3 hues✓ pass · CVD ΔE 6.7 with ■ + underline

Every role also has a non-color carrier: weight, quotes, $, underline. Paper drops the choice hue and uses weight. Studies of syntax color show modest and mixed gains, so fewer, reliable hues cost little. Every value passes 4.5:1 in the worst case, on the input and on the translucent surface. The Paper error red sits in the 6–8 ΔE band, which is allowed only because errors also carry ■ and the underline.

F · HOW IT RENDERS IN UI TOOLKIT
  1. The TextField does not take rich text, so its text is transparent and keeps the caret and selection. A rich-text Label on top draws the colors.
  2. The font is monospaced, so a token's x is its column times the glyph width. The wavy underline and the ghost text are positioned this way, with no text measuring.
  3. Rebuild only when the value changes: tokenize, classify, write <color> spans with a pooled StringBuilder. Budget: one string per keystroke and nothing on idle frames.
  4. Roles are --dxt-syn-number, -string and -choice. Command uses ink, ghost text uses ink-muted, errors use error-text. They are read once per theme change into a color table.
