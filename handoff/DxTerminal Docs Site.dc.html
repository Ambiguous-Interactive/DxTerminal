01 · Commands

Write a method. Get a command.

The source generator reads the signature. Ranges, choices, and defaults become typed arguments with completion and validation.

No reflection sweep at startup. Stripped player builds keep every command the build profile allows.

public static class CheatCommands
{
[RegisterCommand("heal", Help = "Heals a target",
Group = "Cheats", Tier = CommandTier.Tester)]
public static void Heal(
[Arg(Min = 1, Max = 100)] int amount,
[Arg(Choices = new[] { "self", "ally", "enemy" })] string target = "self")
{
Terminal.Log("Healed {0} for {1} HP.", target, amount);
}
}

Guides › Commands

Commands

A command is a name, a handler, and typed arguments. Declare a static command with an attribute, or an instance command from a component.

Static commands

Mark a static method with [RegisterCommand]. Parameters become arguments; [Arg] adds ranges and choices.

Instance commands

Derive TerminalCommandBehaviour when a command needs scene state. Each Register call keeps a handle, and the base class disposes the handles when the component disables.

public sealed class InventoryCommands : TerminalCommandBehaviour
{
[SerializeField] private Inventory _inventory;
protected override void RegisterCommands()
{
Register(CommandBuilder
.Create("pickup", "Picks up an item")
.Arg<string>("item", spec => spec
.Required()
.Choices(context => _inventory.ItemNames))
.Handler((context, arguments) =>
_inventory.Pickup(arguments.Get<string>("item"))));
}
}
Note Commands default to the Developer tier. A Release build runs them only if its build profile enables Developer.
